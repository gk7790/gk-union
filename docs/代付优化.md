可以。代付优化方案和代收相似，但优先级不同：**代付最核心是资金安全，速度优化不能绕过余额冻结、收款信息校验、路由可用性。**

推荐目标是：

```text
先确认能不能付、付给谁、走哪家 PSP
再冻结资金
再提交 PSP
后续通知、查单、报表异步
```

**推荐代付主流程**

```text
1. app_id 鉴权 / 签名 / IP / 商户状态
2. 幂等校验 merchant_order_id
3. 校验 amount / currency / country_code / method_code
4. 校验 payee 收款人信息
5. 如果是 BANK_TRANSFER，校验 sys_bank + psp_bank_mapping
6. resolvePayoutPlan 匹配完整方案
7. 计算商户手续费和 total_debit_amount
8. 创建平台代付订单，保存快照
9. 冻结商户余额
10. 提交 PSP 代付
11. 返回商户 PROCESSING / FAILED
12. 异步查单、通知、报表、成本核算
```

**同步步骤，失败就停止**

| 步骤 | 原因 |
|---|---|
| 鉴权、签名、IP | 请求是否合法 |
| 幂等校验 | 避免重复出款 |
| 金额、币种、国家、方式 | 基础订单合法性 |
| 商户应用权限 | 商户是否允许该方式代付 |
| 收款人信息校验 | PSP 提交必须依赖 |
| 银行映射 | 银行代付必须提前拿到 PSP bank_code |
| 商户手续费 | 影响实际冻结金额 |
| total_debit_amount | 影响商户余额冻结 |
| PSP 路由 | 没路由不能冻结后再发现不可提交 |
| PSP method/account | 没账号不能提交 |
| 创建订单 | 资金和 PSP 请求必须有平台单承接 |
| 冻结余额 | 冻结失败不能请求 PSP |
| 提交 PSP | 代付创建结果通常要同步拿到 |

**可以异步的步骤**

```text
PSP 成本手续费补算
利润统计
报表统计
商户异步通知
主动查单
PSP 状态补偿
失败告警
操作审计扩展日志
风控后置分析
```

但注意：如果 PSP 成本费率会参与“是否允许出款”或“选择哪条路由”，那它也必须同步。

**最值得优化的地方**

第一，做 `resolvePayoutPlan`。

不要在代付流程里散着查：

```text
merchant_fee_rule
psp_route_rule
psp_method
psp_account
psp_bank_mapping
psp_fee_rule
```

建议封装成：

```text
resolvePayoutPlan(merchant, app, currency, country_code, method_code, amount, payee)
```

返回：

```text
merchant_fee_rule
merchant_fee_amount
total_debit_amount
route_rule
psp_provider
psp_method
psp_account
bank_mapping
psp_fee_rule
psp_fee_amount
```

第二，路由前置到冻结之前。

你现在的代付逻辑如果是：

```text
创建订单 -> 冻结余额 -> 匹配路由 -> 请求 PSP
```

建议优化为：

```text
匹配路由 -> 创建订单 -> 冻结余额 -> 请求 PSP
```

这样可以避免“余额已经冻结了，结果发现没有可用 PSP 路由”，减少释放冻结的补偿压力。

第三，银行代付提前校验。

如果：

```text
method_code = BANK_TRANSFER
```

则必须同步校验：

```text
商户传入 bank_code / bank_id
sys_bank 存在且启用
当前 PSP 有 psp_bank_mapping
映射出的 psp_bank_code 不为空
```

否则不要冻结，不要请求 PSP。

第四，配置预检。

后台配置时就检查完整链路：

```text
商户费率是否存在
PSP 路由是否存在
PSP method 是否正常
PSP account 是否正常
银行方式是否配置 bank mapping
PSP payout adapter 是否支持该 method
```

这比下单时才失败更重要。

第五，缓存代付配置。

适合缓存：

```text
merchant_app
merchant_fee_rule
psp_route_rule
psp_method
psp_account
psp_bank_mapping
psp_fee_rule
```

缓存 key 可以包含：

```text
tenant_id
merchant_id
merchant_app_id
country_code
currency
method_code
direction=PAYOUT
bank_code
amount_range
```

后台改配置时主动清缓存。

**PSP 超时处理**

代付这里尤其重要。提交 PSP 时如果超时，不要简单标记失败并释放冻结，因为 PSP 可能已经受理。

建议状态：

```text
SUBMIT_UNKNOWN / PROCESSING
```

然后：

```text
保留冻结
记录 psp_request_log
异步查单
查到 PSP 不存在 -> 释放冻结，订单失败
查到 PSP 处理中 -> 保持冻结
查到 PSP 成功 -> 扣减冻结
查到 PSP 失败 -> 释放冻结
```

**最终推荐版本**

```text
同步主链路：
鉴权 -> 幂等 -> 参数/payee/bank校验 -> resolvePayoutPlan -> 商户费率 -> 创建订单 -> 冻结余额 -> 提交 PSP

异步补偿链路：
查单 -> 成功扣冻结 -> 失败释放冻结 -> 商户通知 -> 报表/利润/告警
```

代付优化的核心不是把更多步骤异步，而是：**在冻结前把所有“能不能提交 PSP”的问题解决掉，在提交 PSP 后把所有“不确定状态”交给查单补偿。**
