
可以优化，但建议按优先级来，不要一上来把所有东西都异步。代收下单真正慢的地方一般是：

```text
多次查配置表
规则匹配复杂
PSP HTTP 请求慢
日志/状态记录写库多
配置缺失导致实时失败
```

我建议你按这几个方向优化。

**第一优先级：做配置预检**

这是最重要的。不要等商户请求来了才发现：

```text
商户费率不存在
PSP 路由不存在
PSP method 不存在
PSP account 停用
PSP fee rule 不存在
```

后台配置时就要做“发布校验”。比如配置一个 `PAYIN + PHP + MAYA`，系统立刻检查完整链路：

```text
merchant_fee_rule
psp_route_rule
psp_method
psp_account
psp_provider
psp_fee_rule 可选
```

这样商户下单时少很多异常分支，速度也更稳定。

**第二优先级：做 PayinPlan 一次性解析**

不要让下单流程到处散着查：

```text
查商户费率
查路由
查 PSP method
查 PSP account
查 PSP fee
```

可以抽成一个统一方法：

```text
resolvePayinPlan(app_id, merchant_id, currency, country_code, method_code, amount)
```

它一次返回：

```text
merchant_fee_rule
merchant_fee_amount
settle_amount
route_rule
psp_provider
psp_method
psp_account
psp_fee_rule
psp_fee_amount
```

然后订单直接保存这些快照。这样代码更清楚，也方便缓存。

**第三优先级：缓存配置**

这些表非常适合缓存：

```text
merchant_app
merchant
merchant_fee_rule
psp_route_rule
psp_method
psp_account
psp_provider
psp_fee_rule
```

缓存 key 可以按业务维度设计：

```text
tenant_id + merchant_id + app_id + country_code + currency + method_code + direction
```

金额区间和时间段要注意，不能简单只按 `method_code` 缓存。可以缓存规则列表，然后内存里匹配金额；或者缓存命中的 plan，TTL 短一点，比如 30 秒到 2 分钟。

后台修改配置时，主动清缓存。

**第四优先级：把非核心写入异步化**

代收主链路必须同步的是：

```text
鉴权
幂等
商户费率
结算金额
PSP 路由
创建订单
请求 PSP
返回 pay_url
```

可以异步的是：

```text
商户请求日志
部分状态日志
PSP 成本补算
报表统计
利润统计
告警
商户 notify
主动查单
```

不过订单主表一定要同步保存，PSP 请求日志也建议至少保证可靠落库或进入 outbox，不然排查问题会很痛。

**第五优先级：优化 PSP 请求**

代收最终要返回 `pay_url`，所以请求 PSP 通常绕不开。这里优化点是：

```text
HTTP 连接池
短连接超时
读取超时
PSP 熔断
PSP 健康状态
慢 PSP 自动降权
失败路由切换
```

比如 PSP A 经常 3 秒才返回，就不要每次都卡住。可以把它临时标记为降级，让路由优先走 PSP B。

**第六优先级：数据库查询和索引**

你现在 `psp_route_rule` 已经有匹配索引，这是对的。还要确保这些表都有高频查询索引：

```text
merchant_fee_rule:
tenant_id, merchant_id, merchant_app_id, direction, currency, method_code, status, priority

psp_fee_rule:
tenant_id, psp_id, psp_account_id, psp_method_id, direction, currency, method_code, status, priority

psp_method:
psp_id, country_code, currency, method_code, direction, status

psp_account:
tenant_id, psp_id, status
```

规则查询尽量做到“查最优一条”，不要查一堆再 Java 里慢慢筛，除非你已经缓存到内存。

最终推荐流程：

```text
1. 同步鉴权、签名、幂等
2. resolvePayinPlan 从缓存/DB 拿完整方案
3. 同步计算商户手续费和结算金额
4. 同步保存订单和快照
5. 同步请求 PSP 拿 pay_url
6. 异步写日志、通知、查单、报表、成本补偿
```

最值得先做的是：**配置预检 + PayinPlan + 配置缓存**。这三个做完，代收链路会稳很多，也不会因为某张规则表临时没配导致商户请求时才卡死。
